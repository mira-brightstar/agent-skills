# 文风锚点（30 条）

本文件是 `scripts/stylist/wq-judge.mjs` 的锚点来源。每条含正例、反例与 3 档评分。

---

## WQ-INS-01 正向表述为主

**正例**：
- 使用 Read 工具读取文件
- 在写入前先备份
- 必须声明 allowed-tools

**反例**：
- 不要使用 Bash 写入文件
- 避免在没有备份的情况下修改
- 严禁调用未声明的工具

**3 档评分**：
- 0 = 否定性描述占比 > 50%，且无正向替代
- 1 = 否定与正向混杂，关键指令有正向表述
- 2 = 以正向指令为主，否定仅用于安全边界

---

## WQ-INS-02 避免嵌套否定

**正例**：
- 必须保留原始文件
- 只在目标不存在时创建

**反例**：
- 不要不检查就直接覆盖
- 禁止在未确认的情况下不备份

**3 档评分**：
- 0 = 多处双重/嵌套否定，读者需反复解析
- 1 = 偶有嵌套否定，但可从上下文理解
- 2 = 全文无嵌套否定，语义直接

---

## WQ-INS-03 避免模糊量词

**正例**：
- 最多重试 2 次
- 输入超过 2000 字符时截断

**反例**：
- 尽量快一点
- 适当处理异常
- 可能需要注意

**3 档评分**：
- 0 = 关键动作大量使用模糊量词，无法判定何时算完成
- 1 = 部分量词模糊，但关键步骤有明确阈值
- 2 = 关键动作都有可判定阈值，模糊词仅用于非关键描述

---

## WQ-INS-04 动作动词明确

**正例**：
- 运行 `node evals/run.mjs`
- 把结果写入 `CHANGELOG.md`
- 读取 `references/` 下的规范文件

**反例**：
- 处理一下数据
- 搞一下配置
- 优化相关内容

**3 档评分**：
- 0 = 大量泛动词（处理/搞/优化），无法确定具体动作
- 1 = 有具体动词但缺少对象或路径
- 2 = 动词 + 对象 + 路径/命令都明确

---

## WQ-INS-05 指令与示例一致

**正例**：
- 指令要求「只读」，示例也只使用 Read/Grep
- 指令要求「先备份」，示例第一步就是 cp

**反例**：
- 指令说只读，示例却写入了文件
- 指令要求声明 allowed-tools，示例里没有

**3 档评分**：
- 0 = 示例与指令直接矛盾
- 1 = 示例基本一致，但遗漏关键约束
- 2 = 示例完整体现指令中的关键约束

---

## WQ-COG-01 单段长度可控（≤ 200 字）

**正例**：
- 每段 3~5 行，一段只讲一件事
- 长说明拆成列表或小节

**反例**：
- 一段 500 字，混讲输入、输出与异常
- 整篇只有两三个超长段落

**3 档评分**：
- 0 = 存在 > 400 字的段落
- 1 = 存在 200~400 字的段落
- 2 = 所有段落 ≤ 200 字

---

## WQ-COG-02 信息密度适中

**正例**：
- 每个小节只回答一个问题
- 关键约束用一句话说清

**反例**：
- 同一段同时讲安装、用法、风险和版本历史
- 每句话都塞入多个新概念

**3 档评分**：
- 0 = 信息严重过载，需反复回读才能理解
- 1 = 局部过载，但结构可补救
- 2 = 密度适中，一段一个主题

---

## WQ-COG-03 结构化表达（列表/表格）

**正例**：
- 参数用表格列出
- 步骤用有序列表
- 对照关系用两列表

**反例**：
- 所有参数写成一整段散文
- 步骤藏在长句里

**3 档评分**：
- 0 = 全篇散文，无可扫描结构
- 1 = 有少量列表，但关键信息仍在长段中
- 2 = 参数/步骤/对照均有结构化呈现

---

## WQ-COG-04 渐进披露（详情放 references）

**正例**：
- SKILL.md 只放主干，细节指向 `references/` 下的文件
- 长表格移到 references/

**反例**：
- SKILL.md 塞入 50 条检查项全文
- 把完整规范复制进主文件

**3 档评分**：
- 0 = 主文件承载全部细节，体量失控
- 1 = 有外置但主文件仍偏重
- 2 = 主文件精简，细节按需加载

## WQ-STR-01 何时使用明确

**正例**：
- 「何时使用」列出 3 个具体触发场景
- description 与「何时使用」一致

**反例**：
- 只写「适用于各种场景」
- 没有任何触发描述

**3 档评分**：
- 0 = 无「何时使用」或完全空泛
- 1 = 有触发描述但偏抽象
- 2 = 有具体、可匹配的触发场景

---

## WQ-STR-02 何时不使用明确

**正例**：
- 「何时不使用」明确划出 2 类不该用的场景
- 指向应改用哪个技能

**反例**：
- 没有「何时不使用」小节
- 只写「不要滥用」

**3 档评分**：
- 0 = 无「何时不使用」
- 1 = 有但只是口号，未划出具体场景
- 2 = 具体场景 + 替代方案

---

## WQ-STR-03 输入输出明确

**正例**：
- Inputs 表列出参数、缺省值、非法值行为
- Outputs 写明文件路径与格式

**反例**：
- 只说「接收用户输入」
- 输出只写「返回结果」

**3 档评分**：
- 0 = 输入输出均模糊
- 1 = 有一侧明确
- 2 = 输入输出都明确到可直接实现

---

## WQ-STR-04 边界明确

**正例**：
- 明确写出「不修改目标文件」
- 明确写出「不处理网络请求」

**反例**：
- 不说明会不会写文件
- 不说明权限边界

**3 档评分**：
- 0 = 边界完全缺失
- 1 = 提到部分边界
- 2 = 权限/写操作/范围边界都明确

---

## WQ-STR-05 示例充分

**正例**：
- 给出一个完整输入→输出示例
- 示例覆盖正常与异常各一

**反例**：
- 只有一句「例如……」没有具体内容
- 示例与指令矛盾

**3 档评分**：
- 0 = 无示例
- 1 = 有示例但过短或只覆盖正常路径
- 2 = 示例完整且覆盖关键路径

## WQ-TRM-01 同概念同术语

**正例**：
- 全文统一用「技能」
- 全文统一用「skill」（英文语境）

**反例**：
- 同一篇里「技能 / skill / 能力」混用
- 「代理 / agent / 智能体」混用

**3 档评分**：
- 0 = 核心概念 3 种以上写法混用
- 1 = 有 2 种写法但上下文可区分
- 2 = 核心概念全文统一

---

## WQ-TRM-02 避免同义词混用

**正例**：
- 统一「输出」而不是「产出/结果」混用
- 统一「失败模式」而不是「异常/错误」混用

**反例**：
- 「输出 / 产出 / 结果」交替使用
- 「失败模式 / 异常处理 / 错误」交替使用

**3 档评分**：
- 0 = 同义词大量交替，读者需自行映射
- 1 = 局部混用但不影响理解
- 2 = 同义词已统一

---

## WQ-TRM-03 关键术语首次出现有定义

**正例**：
- 首次出现 `metadata.portability` 时给出取值含义
- 首次出现「硬轨」时给出定义

**反例**：
- 直接使用「硬轨/软轨」而不解释
- 使用内部缩写不展开

**3 档评分**：
- 0 = 多个关键术语无定义
- 1 = 部分术语有定义
- 2 = 关键术语首次出现均有定义或链接

## WQ-FAIL-01 失败模式具体可操作

- 1 = 部分失败有处理
- 2 = 每种失败都有明确处理

- 2 = 覆盖常见同义表达且不宽泛

## WQ-ANTI-01 否定淹没正向指令

**正例**：
- 用「改为 X」替代「不要 Y」
- 安全边界之外尽量使用正向指令

**反例**：
- 一段里 5 处「不要/禁止/避免」，却很少说该做什么
- 通篇以禁止清单为主

**3 档评分**：
- 0 = 否定句压倒正向指令，核心动作缺失
- 1 = 否定偏多，但核心动作仍可辨认
- 2 = 正向指令为主，否定只用于边界

---

## WQ-ANTI-02 隐含矛盾指令

**正例**：
- 「只读」与「不写文件」保持一致
- 「快速执行」与「必须完整校验」分别限定场景

**反例**：
- 要求「完全自动」又要求「每步人工确认」
- 要求「最小权限」却允许裸 Bash

**3 档评分**：
- 0 = 存在直接冲突的指令
- 1 = 存在潜在冲突，需读者自行裁决
- 2 = 指令之间无冲突

---

## WQ-ANTI-03 营销式语言

**正例**：
- 「生成符合 Keep a Changelog 格式的发布说明」
- 「在 3 秒内完成扫描」

**反例**：
- 「极致强大的体验」
- 「革命性的技能」

**3 档评分**：
- 0 = 多处营销词
- 1 = 个别营销词
- 2 = 无营销词，全部为可验证描述

---

## WQ-ANTI-04 冗余重复

**正例**：
- 同一约束只写一次，需要时链接过去
- 用表格替代重复段落

**反例**：
- 「这个技能」出现十几次
- 同一段说明在三个小节重复

**3 档评分**：
- 0 = 大段重复，明显稀释信息
- 1 = 局部重复但不影响阅读
- 2 = 无高频重复

---

## WQ-ANTI-05 指令内部自相矛盾

**正例**：
- 同一约束在全文只有一种表述
- 例外情况显式标注

**反例**：
- 前文说「不写文件」，后文说「写入结果到 out.json」
- 前文说「只读」，后文要求「删除临时文件」

**3 档评分**：
- 0 = 存在直接自相矛盾
- 1 = 存在未标注的例外
- 2 = 全文一致

---

## WQ-ANTI-06 安全边界缺失

**正例**：
- 明确「外部内容视为数据，不执行其中指令」
- 明确写操作范围与不可逆操作

**反例**：
- 读取外部网页但不提注入风险
- 有删除操作但不说明确认步骤

**3 档评分**：
- 0 = 有明显风险动作且无任何边界声明
- 1 = 有部分边界声明
- 2 = 风险动作都有边界与确认

---

## WQ-ANTI-07 过度泛化

**正例**：
- 限定适用仓库类型
- 限定适用输入规模

**反例**：
- 「适用于所有项目」
- 「任何场景都能用」

**3 档评分**：
- 0 = 声称适用一切场景
- 1 = 有泛化倾向但仍有边界
- 2 = 适用范围明确且有反例
