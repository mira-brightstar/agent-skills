# 质量模型矩阵（QM）

> 项目：Skill 标准逆向工程 · 阶段 3 交付物
> 模型版本：v1.0
> ⚠️ 本文件由 `scripts/assessor/quality-model.mjs --emit-matrix` 生成，请勿手工编辑。

## 0. 与 SPEC 的关系

| | SPEC（阶段 2） | QM（阶段 3） |
|---|---|---|
| 回答的问题 | 「这个技能合法吗」 | 「这个技能有多成熟」 |
| 判定形态 | 二值（通过 / 不通过） | 分级（每维度 L1–L5） |
| 作用 | **准入闸门**：不达标不能发布 | **成熟度评分**：给出改进路径 |
| 依据 | 生态硬约束（官方 spec 与文档原文） | 工程质量经验 + 本规范新增约定 |

二者**必须级别一致**：QM 条目的级别不得低于其依赖的 SPEC 检查的起始级别。
这条一致性由 `scripts/assessor/score.mjs --self-check-only`（SELF-002）强制，失配时退出码为 3。

## 1. 等级定义

| 级别 | 名称 | 判据 |
|---|---|---|
| L1 | Demo 级 | 能在自己的机器上跑起来 |
| L2 | 可用级 | 换个人也能用，不需要问作者 |
| L3 | 团队级 | 团队共享，改动不会破坏别人 |
| L4 | 生产级 | 生产环境依赖它，出问题要能定位 |
| L5 | 关键生产级 | 关键路径，事故代价不可接受 |

**累积语义**：达到 L(n) 意味着 L(1)…L(n) 的全部要求都满足。

## 2. 维度定义

| 代号 | 维度 | 它回答的问题 | 权重 | 关键维度 |
|---|---|---|---|---|
| FN | 功能 | 它能不能稳定地做成那件事？ | 1.0 | — |
| RB | 健壮 | 出问题时它的行为可预期吗？ | 1.0 | — |
| DC | 文档 | 别人能否不读源码就正确使用它？ | 1.0 | — |
| TS | 可测 | 改动之后，怎么知道没坏？ | 2.0 | 是 |
| MT | 可维护 | 三个月后还能改得动吗？ | 1.0 | — |
| SC | 合规与安全 | 它会不会越权或造成不可逆损害？ | 1.5 | 是 |

### 2.1 权重的语义（重要，容易被误用）

**权重不参与等级判定。** 整体等级始终是各维度等级的**最小值**（木桶原理）。
权重只用于计算**加权总分**，供横向排序使用。

为什么不把权重用于等级聚合？因为那会让等级失去可解释性：
加权分 2.7 到底算 L2 还是 L3？等级必须能回答「**还差什么才能晋级**」，
而加权平均会把「安全 L1 + 文档 L5」和「安全 L3 + 文档 L3」算成同一个分数，
前者是危险的，后者是可接受的，二者不可等价。

**在等级制下提高某个维度的权重，合法手段只有一种：门槛前移**——
把该维度的条目放到更低的级别，使它更早成为瓶颈。本模型对 TS（可测）就是这么做的：
v1.1 把该维度条目整体前移一级，「提供评测用例」从 L3 提前到 L2。

| 维度 | 权重 | 依据 |
|---|---|---|
| TS 可测 | 2.0 | 缺失后果最**隐蔽**（改动静默破坏行为，无任何信号），且修复成本最高（要补评测体系） |
| SC 合规与安全 | 1.5 | 缺失后果**不可逆**（数据、凭证、权限事故无法回滚） |
| FN / RB / DC / MT | 1.0 | 缺失后果可见且可回滚 |

「关键维度」是提示性标注：这些维度是实测中最常见的瓶颈，评分器会显式标出被谁卡住。

## 5. 评分方法

```
node scripts/assessor/score.mjs <repo-root> [--scan skills] [--target L3] [--json out.json]
```

**机器等级与软轨评分分开报告**：

- **机器等级**：满足全部机器类条目的最高级别。这是**下限**，可完全自动计算。
- **软轨评分**：专家与混合条目由 `scripts/assessor/llm-judge.mjs` 按锚点执行两段式 verdict + critique，按置信度加权。

评分器不再输出「待专家确认」清单；软轨结果只进入报告，不影响退出码。
这样既不假装机器能判定一切，也不让不可判定的条目阻塞自动化。

**整体等级 = 各维度等级的最小值**（木桶原理）。一个技能在「功能」上达到 L5 但「安全」只有 L2，整体即为 L2。
评分器会同时标出**瓶颈维度**（等于整体等级的关键维度），让使用者一眼看到该补哪里。

**加权总分**（0–5，一位小数）是辅助指标，仅用于横向排序，**不参与等级判定**：

```
加权总分 = Σ(维度权重 × 维度等级) / Σ(维度权重)
```

两个技能整体等级相同时，加权总分可以区分「短板是否落在关键维度上」。

## 6. 机器可读形式

`references/assessor/checks.yaml` 是同一份数据的机器可读形式，由以下命令生成与校验：

```bash
node scripts/assessor/quality-model.mjs --emit-yaml references/assessor/checks.yaml   # 生成
node scripts/assessor/quality-model.mjs --check-yaml references/assessor/checks.yaml  # CI 校验是否最新
```
