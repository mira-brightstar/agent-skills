# 软轨条目锚点（技能评定官）

本文件是 `scripts/assessor/llm-judge.mjs` 的**唯一真相源**。每条包含：维度、级别、条目要求、正例、反例、3 档评分、LLM Prompt。

约定：
- `score` 统一为 `0 | 1 | 2`；`result` 由阈值换算：`score >= 1` → `pass`，否则 `fail`；证据不足或要求对该技能无意义 → `na`。
- Prompt 中的 `{skill_name}` 与 `{skill_content}` 会被脚本替换。
- 所有 Prompt 只要求模型返回 JSON，禁止输出解释性前后缀。

---

## QM-FN-L1b

**维度**：FN 功能
**级别**：L1
**条目**：description 能让人与模型判断出「这是干什么的」
**阈值**：得分 >= 1

**正例**：
- "Generate release notes from git history and print a changelog grouped by change type."
- "Diagnose failing tests by reproducing the failure before proposing a fix."

**反例**：
- "A powerful skill for developers."
- "Helps you do things better."

**3 档评分**：
- 0 = 只有形容词或空泛承诺，看不出具体动作与对象
- 1 = 能看出做什么，但缺少对象或触发场景
- 2 = 动作、对象、产出都清楚，人或模型可据此触发

**LLM Prompt**：
```text
你是 AI Agent Skill 评审专家。请判断该 skill 的 description 能否让人与模型判断出「这是干什么的」。

【判定标准】
- 看动作 + 对象 + 产出是否具体，而不是看文案是否漂亮。
- 只有形容词、空泛承诺 => 0；能看出做什么但缺对象或场景 => 1；三者清楚 => 2。

【技能名】{skill_name}
【技能内容】
{skill_content}

【输出格式】只返回 JSON：
{"result":"pass|fail|na","score":0|1|2,"reason":"简短理由","evidence":"引用原文片段"}
```
