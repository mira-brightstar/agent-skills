# 退出码语义（技能评定官）

四个硬轨脚本共用同一套退出码。**软轨 `llm-judge.mjs` 不参与退出码判定。**

| 码 | 含义 | 处置 |
|---|---|---|
| `0` | 通过 | 可继续 |
| `1` | 硬轨存在 MUST 失败 / 未达目标级别 | 修技能，不改标准 |
| `2` | 参数或路径错误 | 修命令，不修技能 |
| `3` | 工具链自检失败（标准自身有问题） | 修标准，不修技能 |

`3` 与 `1` 必须严格区分：前者说明标准坏了，后者说明技能不合格。

---

## 各脚本的退出码来源

### validate.mjs

| 码 | 条件 |
|---|---|
| 0 | 指定 `--level` 下无 `MUST` 失败 |
| 1 | 存在 `MUST` 失败 |
| 2 | 仓库/技能路径不存在，或 `--level` 非法 |
| 3 | `SELF-001` 失败（字段白名单与 JSON Schema 漂移） |

### score.mjs

| 码 | 条件 |
|---|---|
| 0 | 无目标级别，或所有技能达到 `--target` |
| 1 | 最低等级低于 `--target` |
| 2 | 路径不存在或参数非法 |
| 3 | `SELF-002`（SPEC 与 QM 级别失配）或 `SELF-003`（锚点缺失）失败 |

### audit.mjs

| 码 | 条件 |
|---|---|
| 0 | 无 `MUST` 违反 |
| 1 | 存在 `MUST` 违反（`SHOULD` 失败不计入） |
| 2 | 路径不存在 |

### sensitivity.mjs

| 码 | 条件 |
|---|---|
| 0 | 基线干净，且 9 个注入缺陷全部被抓住 |
| 1 | 基线不干净，或存在未被抓住的缺陷（标准有盲区） |
| 2 | 技能目录不存在 |

### llm-judge.mjs（软轨）

| 码 | 条件 |
|---|---|
| 0 | 判定正常完成（无论判定结果如何） |
| 2 | 参数/路径错误，或 LLM 调用失败 |
| 3 | `SELF-005` 失败（软轨锚点不完备） |

---

## 综合退出码

当一次评审同时跑多个硬轨脚本时，按优先级汇总（不是简单取最大值）：

```text
综合退出码 = 3 若任一项为 3
           = 1 若任一项为 1
           = 2 若任一项为 2
           = 0 否则
```

与 `max()` 的差别只在同时出现 `1` 与 `2` 时：按优先级应报 `1`（技能不合格），而不是 `2`（命令写错），因为此时脚本已经成功跑完并给出了判定。任何一项为 `3`，综合即为 `3`：先修标准，再看技能。软轨结果只进入报告，不参与汇总。

编排层（`scripts/conductor.mjs`）在综合退出码非 0 时跳过软轨与文风师，并显式说明原因；退出码仍等于上述综合值。硬轨内部四个脚本始终全部执行，不互相短路。
